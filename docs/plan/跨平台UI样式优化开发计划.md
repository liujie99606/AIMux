# 跨平台 UI 样式优化开发计划

## 1. 背景

当前 AIMux 在 Windows 上的界面基本可用，但在 macOS 上出现了明显的视觉不一致。账号新增/编辑弹窗是最集中的表现：窗口标题栏是 macOS 原生浅色样式，内容区域是深色主题，输入框、下拉框、数值框、列表和表格的尺寸及边框也不统一。

这不是单个页面的孤立问题，而是 Qt 原生控件、`qdarktheme` 全局主题、主窗口局部样式和组件局部样式叠加后的跨平台差异。账号表单作为第一个优化页面，用于验证统一主题和布局方案，再逐步覆盖其他页面。

## 2. 目标

- Windows 和 macOS 的控件颜色、边框、圆角、字体和间距保持一致。
- 账号新增/编辑弹窗字段对齐、宽度合理、控件高度统一。
- 输入框、下拉框、SpinBox、列表、表格和按钮在不同平台有稳定尺寸。
- 保留 macOS 原生窗口操作习惯，不因追求标题栏全深色而引入不必要的无边框窗口风险。
- 样式集中维护，减少页面和组件中重复的颜色字符串。
- 优化过程不改变现有业务逻辑、字段校验和交互语义。

## 3. 账号表单现状分析

主要代码位于 `app/ui/components/accounts/account_form.py`。

### 3.1 窗口装饰

- macOS 顶部白色标题栏和红黄绿按钮属于系统原生窗口装饰，不受普通 Qt 样式表完全控制。
- 当前内容区域由 `qdarktheme.setup_theme("dark")` 控制，因此形成深色内容区加浅色原生标题栏的组合。
- 首期保留原生标题栏，不做自定义无边框标题栏；后者需要自行处理窗口拖动、关闭、最小化和最大化，风险较高。

### 3.2 表单布局

当前直接使用 `QFormLayout`，没有统一设置：

- 标签列宽度和对齐方式。
- 字段控件的最小宽度、最大宽度和尺寸策略。
- 行间距、字段间距和表单边距。
- 普通输入框、模型列表、模型映射表和备注区域的宽度比例。

因此 macOS 下会出现普通输入框偏窄、模型映射表偏宽、标签和备注区域宽度不一致、右侧空白较大的问题。

### 3.3 控件样式

账号表单中的 `QLineEdit`、`QComboBox`、`QSpinBox`、`QDoubleSpinBox`、`QListWidget`、`QTableWidget` 和 `QDialogButtonBox` 没有统一的项目级样式，部分外观依赖 macOS 原生 `QStyle`，导致：

- 输入框背景和边框深浅不一致。
- 下拉框和数值框高度不同。
- 列表、映射表和备注框的边框风格不同。
- 聚焦边框、选中状态和按钮颜色不一致。

## 4. 推荐技术方案

### 4.1 抽取统一主题模块

新增 `app/ui/theme.py`，集中维护：

- 应用级颜色和字体常量。
- 输入控件、下拉框、数值框、列表、表格和按钮样式。
- 表格表头、选中行、滚动条和聚焦状态。
- 弹窗内容区域和校验提示样式。
- Windows/macOS 需要的少量平台差异。

`app/__main__.py` 只负责初始化主题，页面和组件尽量不再重复拼接颜色字符串。现有状态按钮、监控状态格、测试日志等特殊组件可以保留独立状态色，但颜色应引用统一主题常量。

### 4.2 账号表单布局标准化

在 `AccountForm` 中统一设置：

- 表单边距和行间距。
- 标签列固定宽度并右对齐。
- 普通字段统一最小宽度和高度。
- 模型列表、模型映射表和备注区域使用明确的宽度/高度约束。
- 所有可扩展字段使用 `QSizePolicy.Expanding`，避免 macOS 下只按内容首选尺寸显示。
- 底部保存/取消按钮保持统一宽度和间距。

### 4.3 Qt 样式策略

优先继续使用 `qdarktheme` 提供基础深色主题，再由项目主题模块补齐业务控件样式。是否切换到 Qt `Fusion` 风格，需要在 macOS 和 Windows 实机分别对比后决定：

- `Fusion` 更容易得到跨平台一致的控件尺寸和绘制结果。
- 直接切换可能改变现有 Windows 外观，不能未经视觉验证全局启用。

## 6. 影响范围

预计涉及以下模块：

- `app/__main__.py`：主题初始化入口。
- `app/ui/theme.py`：新增统一主题模块。
- `app/ui/main_window.py`：减少重复样式，保留页面级布局样式。
- `app/ui/components/accounts/account_form.py`：第一阶段重点改造。
- `app/ui/components/common/data_table.py`：公共表格基础样式。
- `app/ui/components/accounts/`：账号按钮、状态和测试组件。
- `app/ui/components/usage/`：使用记录筛选、表格和详情组件。
- `app/ui/components/monitor_*.py`：监控表格、状态格和提示样式。
- `app/ui/views/settings_view.py`、`models_view.py`、`usage_view.py`、`monitor_view.py`：页面级间距和工具栏适配。

本计划只涉及 UI 样式和布局，不涉及数据库、API 契约、调度算法或业务数据，因此不需要 migration。

## 7. 风险与处理

### 7.1 全局样式回归

主题模块会影响所有页面。每次修改公共样式后，需要至少运行对应 UI 测试，并在 Windows/macOS 实机查看主要页面。

### 7.2 原生标题栏无法完全统一

普通 Qt 样式表无法可靠控制 macOS 原生标题栏。首期接受标题栏与内容区域存在平台差异；只有在内容区域统一后仍有明显问题，才单独评估自定义标题栏。

### 7.3 Fusion 风格改变现有 Windows 外观

切换 Qt 基础风格可能影响按钮、菜单、滚动条和表格。必须先做对比截图，确认收益大于回归风险后再决定。

### 7.4 无头测试无法覆盖真实视觉效果

现有 PySide6 测试主要验证控件结构和交互，不能代替 macOS/Windows 实机视觉检查。重要阶段需要截图对比和人工验收。

## 8. 测试和验收标准

### 8.1 自动化测试

- 账号表单现有必填校验、模型选择、模型映射、保存和取消行为不变。
- 公共表格的列数、表头、行数、按钮和状态控件不回归。
- 测试弹窗、详情弹窗和设置页面仍可正常构造。
- 按改动范围运行聚焦 UI 测试；跨页面主题改动完成后再运行全量测试。

### 8.2 视觉验收

- 账号新增/编辑弹窗在 Windows 和 macOS 中字段标签、输入框左边界一致。
- 普通输入框、下拉框和数值框高度一致，文字不被裁剪。
- 模型列表和映射表不会因平台差异出现异常窄、高或横向溢出。
- 内容区域颜色、边框、聚焦状态和按钮层级一致。
- 深色背景上的文字、错误提示和占位文字清晰可读。
- 窗口缩放后没有控件重叠、文字截断或大片无意义空白。

## 9. 实施顺序

1. 在 macOS 和 Windows 分别保存账号表单、主窗口、使用记录和监控页面基线截图。
2. 新增主题模块，先只覆盖账号表单控件。
3. 调整 `AccountForm` 的布局策略和尺寸约束。
4. 在 Windows 和 macOS 实机验证第一阶段，修正平台差异。
5. 将主题扩展到公共表格、工具栏和弹窗。
6. 分页面完成视觉验证和聚焦测试。
7. 最后评估是否需要切换 `Fusion` 风格或处理自定义标题栏。
8. 完成后运行与影响范围匹配的测试；发布前再运行全量测试。

## 10. 当前结论

这个问题可以解决，但不是修改一个颜色或一个尺寸就能彻底解决。账号表单适合作为第一阶段，因为它同时包含输入框、下拉框、数值框、列表、表格和弹窗按钮，能够验证大部分跨平台样式策略。推荐先完成第一阶段，再根据 macOS 实机结果决定是否推进全局主题重构。
