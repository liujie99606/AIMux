# AIMux Rust 数据库迁移升级规划

## 1. 目标

Rust 首个版本以当前 AIMux SQLite 数据库的业务表结构为唯一基线，保持表名、字段名、数据类型和已有数据兼容。以后废弃旧运行时，只由 Rust 的 SQLx migrations 管理数据库结构。

数据库固定为用户数据目录下的 `aimux.db`，稳定网关、开发网关和桌面端共用同一文件。数据库文件不按端口或运行模式区分。

## 2. 基线和版本表

`src-tauri/migrations/0001_baseline.sql` 创建当前完整业务结构：`accounts`、`models`、`usage_records`、`monitor_records` 及其索引、约束和历史字段名。该文件一经发布不可修改。

`src-tauri/migrations/0002_placeholder.sql` 仅作为已存在的 SQLx migration 占位。实际字段变化从下一个递增编号开始，例如 `0003_add_xxx.sql`。

SQLx 在数据库 `_sqlx_migrations` 表中记录 migration 版本和校验值。历史数据库中的 `alembic_version` 表可以保留，但 Rust 首个版本不读取、不迁移、不删除它；它不参与 Rust 的版本判断。

## 3. 启动流程

1. 解析用户数据目录并打开 `aimux.db`。
2. 建立 SQLite 连接池并启用必要的 WAL/外键设置。
3. 通过 `sqlx::migrate!` 执行从基线到当前 head 的 pending migration。
4. migration 成功后执行默认模型等幂等业务初始化。
5. 初始化 `AppState`、监控任务和 HTTP 网关。

migration 失败时停止启动，不允许业务层访问半升级数据库；不自动 downgrade，也不猜测修复不兼容的数据库。

## 4. 新增字段流程

每次数据库结构变更必须：

1. 修改 `src-tauri/src/model/` 和对应 `schema/`、DAO、Service。
2. 新增一个递增编号 SQL 文件，包含字段、默认值、索引和必要的数据回填。
3. 在临时数据库副本上验证从 `0001` 到最新 head 的完整升级。
4. 验证旧账号、使用记录、监控记录和配置仍可读取。
5. 补充 Rust 测试，并确认 Tauri 打包会包含 `src-tauri/migrations/`。

普通 DAO/Service 增删改查、查询、排序和分页不需要 migration。

## 5. SQLite 注意事项

- 新增可空字段优先使用 `ALTER TABLE ... ADD COLUMN`；需要修改约束、重命名或删除字段时使用临时表重建，并在事务中完成。
- migration 不拼接用户输入，所有动态值使用固定 SQL 或参数绑定。
- 破坏性迁移必须在文档中说明备份、恢复和失败处理；不直接删除用户数据库。
- 不把真实数据库、API 密钥或完整请求内容放入测试 fixture 和日志。

## 6. 验证命令

```powershell
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

发布前还要验证 Windows/macOS 产物在没有开发环境时能执行 migration，并且不覆盖用户数据目录中的数据库。
