# 账号管理功能

## 1. 列表和排序

账号管理页启动或点击“刷新”时调用 `GET /api/accounts?limit=200`。顶部可按协议类型（全部、OpenAI、Anthropic）和状态（全部、启用、停用）筛选。列表排序固定为：

1. `active` 启用账号优先于 `disabled` 停用账号。
2. 同状态按优先级降序，9 最先被看到和调度。
3. 同优先级按名称不区分大小写升序。
4. 名称相同按账号 ID 升序作为稳定兜底。

表格包含选择、名称、类型、状态、倍率、优先级、优先级快捷操作、最近使用和操作列。名称和优先级可以直接编辑；账号数据变化后页面会重新读取最新列表。

## 2. 新增、编辑和复制

新增/编辑表单字段为名称、类型、上游地址、API 密钥、优先级、倍率、测试默认模型、支持模型、标签和备注。优先级范围为 0 至 9；倍率必填，范围为 `0.01` 至 `0.30`，默认 `0.10`。测试默认模型可为空，按账号协议类型从模型目录选择。API 密钥以明文回显并可编辑。上游地址会去除末尾 `/`。

支持模型从模型维护目录加载，并随协议类型切换过滤。未勾选任何模型表示该账号支持该协议下的全部模型。编辑时即使某个已保存模型已从目录删除，它仍会在表单中保留，避免无意丢失配置。复制会预填包括倍率和 API 密钥在内的账号字段，并作为新增账号提交。

测试默认模型位于支持模型之后，只能从当前已勾选的支持模型中选择；取消勾选当前测试模型会自动清空该配置并回退到模型维护默认值。它用于账号测试和后台监控。模型选择顺序为：手动测试时明确选择的模型 → 账号测试默认模型 → 模型维护中该协议的默认模型。批量测试选择“使用账号默认模型”时，每个账号按自己的配置分别解析。

API 密钥在本地数据库中明文保存，`AccountView` 返回密钥供编辑表单回显。

## 3. 状态和优先级

状态列是可直接点击的“启用/禁用”按钮。禁用账号不会被调度器选中，但测试成功或失败不会改变这个人工状态。

真实请求成功时优先级 `+1`，失败时 `-1`；连接测试成功时 `+3`，失败时 `-1`。所有调整都限制在 0 至 9。快捷操作列提供 0、3、6、9 四个圆形按钮，点击后直接将账号优先级设置为对应数值，与优先级编辑框使用同一保存逻辑。

## 4. 测试

单账号测试点击“测试”后打开测试弹窗，从当前协议的模型目录选择模型，并发送最小请求（`max_tokens=1`、用户内容为 `ping`）。OpenAI 使用 `/v1/chat/completions`，Anthropic 使用 `/v1/messages`。

批量测试需要先勾选账号，且所有选中账号必须是同一种协议类型；混合类型会提示拆分操作。统一弹窗会在后台线程中逐个调用单账号测试接口，实时展示当前账号、进度和结果；一个账号失败或网络异常不会中断后续账号。

## 5. 管理 API

| 操作 | 接口 |
|---|---|
| 列表 | `GET /api/accounts` |
| 新增 | `POST /api/accounts` |
| 详情 | `GET /api/accounts/{account_id}` |
| 编辑 | `PUT /api/accounts/{account_id}` |
| 删除 | `DELETE /api/accounts/{account_id}` |
| 测试 | `POST /api/accounts/{account_id}/test` |
| 切换状态 | `POST /api/accounts/{account_id}/toggle-status` |
| 调整优先级 | `POST /api/accounts/{account_id}/adjust-priority?delta=<整数>` |

说明：桌面端批量测试只是在统一弹窗中逐个调用单账号测试接口，不再提供单独的批量测试 API。
