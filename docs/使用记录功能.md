# 使用记录功能

## 1. 记录含义

`UsageRecord` 表示一次上游尝试，而不是只表示一次客户端最终请求。一次客户端请求的多次重试共享 `trace_id`，每条记录的 `attempts` 是该尝试在本次请求中的序号。因此一次请求失败 3 次后第 4 次成功，会看到 4 条记录：3 条失败和 1 条成功。

记录字段包括开始/结束时间、总耗时、首 Token 耗时、账号、协议类型、模型、推理强度、接口、是否流式、成功状态、HTTP 状态码、错误码/错误信息、输入/输出/缓存/总 Token、客户端 IP 和尝试序号。缓存 Token 从 `usage.prompt_tokens_details.cached_tokens` 或 `usage.input_tokens_details.cached_tokens` 解析；流式请求会跨 SSE 事件合并后在流结束时落库，即使首块之后发生读取异常，也会记录失败。

## 2. 列表、筛选和分页

使用记录页的筛选条件为账号 ID、模型、协议类型、结果、开始时间和结束时间。时间条件使用 ISO 字符串，服务端按 `started_at` 做范围比较。点击“查询”或“重置”都会回到第一页；切换左侧菜单也会刷新。

筛选栏提供“清除历史记录”按钮。用户选择清除 7、30 或 90 天前的数据后，调用 `DELETE /api/usage/records/expired?days=<天数>`，删除严格早于当前 UTC 时刻指定天数的记录，并返回实际删除数量；不会自动清理，也不会删除指定保留期内的记录。

接口为 `GET /api/usage/records`，默认 `limit=20`，桌面端始终按每页 20 条查询，服务端最大允许 200 条。列表按开始时间倒序，同一时间再按记录 ID 倒序。底部显示当前页/总页数和总记录数。

## 3. 统计和展示

顶部只显示当前页的请求数、成功率和平均耗时。平均耗时由当前页记录的 `duration_ms` 计算，界面复用 `format_duration_ms` 显示为秒（例如 `1234 ms` 显示为 `1.2 s`）；没有值显示 `-`。缓存 Token 继续保存在数据库和详情中，列表列暂时注释隐藏。

失败结果使用更深的红色，超过 10 秒的首 Token 或总耗时使用警示色。表格中的“详情”按钮和双击行都会打开详情弹窗；详情弹窗显示全部关键字段、Token 用量和完整错误信息。

## 4. 数据来源和接口

`GET /api/usage/records` 返回 `items`、`total` 和同筛选条件的 `summary`。`GET /api/usage/records/{record_id}` 返回单条完整记录。统计由数据库实时聚合，但桌面顶部展示的是当前页统计，避免列表内容和指标范围不一致。

`GET /api/usage/statistics` 返回按服务端本地日期划分的 `today` 与 `yesterday` 两组数据，每组包含 `total_tokens`、`input_tokens`、`output_tokens`、`cached_tokens` 和 `cache_rate`。`accounts_today` 按账号管理的排序返回当前启用账号的今日 Token 汇总，没有今日记录的启用账号保留为零值，禁用账号不返回。缓存率定义为 `cached_tokens / input_tokens`，没有输入 Token 时为 `null`；每个账号还返回 `recent_cache_rate` 和 `recent_cache_count`，统计当前时间往前 2 小时内最近 20 条有效记录（输入 Token 大于 0 且缓存 Token 不为空），按输入 Token 加权计算。数据统计页面将 Token 数值格式化为 K、M、B 等紧凑单位，并将缓存率显示为百分比。

失败记录来自两类路径：真实请求上游返回非 2xx 或抛出超时/连接异常时，调度器立即写入；连接测试成功/失败也会更新账号状态和最近错误，但测试结果不是普通客户端请求的使用记录。
