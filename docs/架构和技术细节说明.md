# AIMux 架构和技术细节说明

## 1. 项目定位

AIMux 是运行在本机的 OpenAI/Anthropic 账号池和兼容网关。客户端连接本机地址，AIMux 负责在同协议账号之间选择上游、原样转发请求、失败重试、记录每次尝试并提供管理页面。

当前正式实现为 Rust/Tauri 2/Vue 3。

## 2. 运行结构

- Tauri 2 启动桌面窗口，并在同一进程中启动 Rust HTTP 网关。
- Axum 提供管理 API、OpenAI/Anthropic 兼容 API 和健康检查。
- Vue 3 + Vite + Element Plus 提供账号、模型、使用记录、监控、统计和设置页面。
- `aimux-gateway` 是可独立启动的 Rust 网关二进制；正式桌面版使用 `aimux` 二进制。
- 稳定后端使用 `7789`，开发后端使用 `7790`；端口统一配置在 `config/runtime-ports.json`。

网关启动后初始化日志、设置、数据库和共享 `AppState`，再启动监控后台任务与 Axum server。Tauri 窗口只通过前端 API 调用管理接口，不直接操作数据库。

## 3. 分层

后端遵循 `controller -> service -> dao -> model`：

- `controller/`：路由、请求参数、认证、状态码和响应组装。
- `service/`：账号调度、模型维护、监控、统计、设置和使用记录业务规则。
- `dao/`：SQLx 查询、分页、排序和持久化。
- `model/`：SQLite 对应的 Rust 数据结构。
- `schema/`：管理 API 和兼容 API 的输入输出类型。
- `gateway/`：OpenAI/Anthropic 请求转发、认证、SSE 流式生命周期。
- `upstream/`：Reqwest 客户端、代理、超时和上游错误处理。
- `background/`：监控等后台任务。

前端遵循 `api -> store -> page/component`：

- `src/api/` 统一 HTTP 请求和类型。
- `src/stores/` 保存跨页面状态。
- `src/pages/` 负责页面级查询、筛选和刷新。
- `src/components/` 负责表单、弹窗、表格和可复用展示。

## 4. 请求和调度链路

1. controller 校验协议、模型、认证和 JSON 请求体。
2. service 根据协议、客户端模型、启用状态、优先级降序和倍率升序选择账号。
3. 对当前账号解析模型映射，生成本次上游请求副本；客户端模型仍保留在使用记录中。
4. upstream 使用账号密钥、上游地址、代理和超时发送请求。
5. 非流式请求直接解析响应和 usage；流式请求在首个请求时创建记录，在 SSE 结束或读取异常时更新记录。
6. 成功或失败按照调度规则更新账号优先级，并返回原协议响应。

每次重试都会重新执行账号选择，不能复用上一轮账号。OpenAI 和 Anthropic 不互相转换，不修改提示词、消息或缓存相关字段。

## 5. 数据库和存储

数据库为 SQLite，固定使用用户数据目录中的 `aimux.db`：

- Windows：`%APPDATA%\\quietforge\\AIMux\\data\\aimux.db`
- macOS：`~/Library/Application Support/quietforge/AIMux/data/aimux.db`

日志位于同一数据目录下的 `log/`，由 `tracing-subscriber` 按天记录应用、请求和错误日志。

SQLx migration 位于 `src-tauri/migrations/`。`0001_baseline.sql` 是 Rust 首个版本的完整业务表基线，后续只追加编号 SQL migration。SQLx 使用 `_sqlx_migrations` 记录版本；历史 `alembic_version` 表保留在旧数据库中，但 Rust 不再读取或维护它。

账号表保留历史字段名 `api_key_encrypted` 以兼容已有数据库，当前内容按产品约定保存本机明文。使用记录包含输入、输出、缓存和总 Token；流式结束时从 SSE usage 事件补齐这些字段。

## 6. 管理 API 和兼容 API

管理 API：`/api/accounts`、`/api/models`、`/api/usage`、`/api/monitor`、`/api/statistics`、`/api/settings`。

OpenAI 兼容端点包括 `/v1/models`、`/v1/chat/completions`、`/v1/completions`、`/v1/responses`、`/v1/embeddings`、`/v1/moderations`、`/v1/images/generations`、`/v1/audio/speech` 和 `/v1/rerank`。

Anthropic 兼容端点包括 `/v1/messages`、`/v1/messages/count_tokens`、`/v1/messages/batches` 和 `/v1/complete`。

管理 API 和兼容 API 使用设置中的本地令牌保护。客户端协议头按白名单透传，上游认证头由选中账号配置注入。

## 7. 构建和验证

前端：`npm run format:check`、`npm run build`。

Rust：`cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`、`cargo check --manifest-path src-tauri/Cargo.toml`、`cargo test --manifest-path src-tauri/Cargo.toml --tests`。集成测试统一位于 `src-tauri/tests/`。

Windows 和 macOS 发布由 `.github/workflows/build-release.yml` 使用 Tauri CLI 构建。正式产物未配置 Apple 公证或 Windows 代码签名。
