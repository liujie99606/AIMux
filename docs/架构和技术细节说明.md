# AIMux 架构和技术细节说明

## 1. 项目定位

AIMux 是运行在本机的 OpenAI/Anthropic 账号池和兼容网关。客户端只需要连接本机地址，AIMux 负责在同协议账号之间选择上游、转发请求、失败重试和记录每次尝试。

项目有两个并行部分：

- FastAPI/uvicorn 本地服务：提供管理 API、兼容协议 API 和 SQLite 持久化。
- PySide6 桌面端：提供账号管理、使用记录、模型维护、监控和设置页面。

AIMux 不做 OpenAI 与 Anthropic 协议转换，不上传账号信息，也不把使用记录用于计费。

## 2. 运行结构

启动入口是 `python -m app`（或安装后的 `aimux` 命令）。桌面模式先在守护线程启动 uvicorn，等待服务就绪后创建 Qt 主窗口；`--server-only` 只启动 API 服务。默认监听 `127.0.0.1:7788`，启动前会检查端口，已经有实例时桌面模式提示用户并退出。

桌面端通过 `ApiClient` 调用本地 API。主窗口左侧导航对应一个 `QStackedWidget` 页面；每次切换页面都会调用该页面的 `refresh()`，重新读取最新数据。左侧菜单的 `CurrentTimeLabel` 使用 `QTimer` 每秒刷新本机时间。账号连接测试的网络请求使用 `AccountTestWorker(QThread)`，避免同步 HTTP 请求阻塞 Qt 事件循环。

## 3. 分层

请求业务遵循 `controller -> service -> dao -> models`：

- `controller` 负责路由、参数、权限和响应组装。
- `service` 负责加密、字段映射、优先级和模型默认值等业务规则。
- `dao` 负责 SQLModel 查询、过滤、排序和持久化。
- `models.py` 定义 `Account`、`CatalogModel`、`UsageRecord`、`MonitorRecord` 四张表。
- `app/ui/views` 负责页面和 API 调用，`app/ui/components` 负责可复用表格、表单和弹窗。

## 4. 数据库和存储

数据库是 SQLite。启动时 `configure_database()` 创建表和索引，并幂等补充默认模型及旧库缺失列。默认数据目录由 `platformdirs` 决定：Windows 为 `%APPDATA%\\aimux`，macOS 为 `~/Library/Application Support/aimux`；设置中的 `db_path` 非空时优先使用该路径。

账号 API 密钥使用由当前操作系统、机器名和网卡地址派生的 Fernet 密钥加密后写入 `api_key_encrypted`，管理接口永不返回明文密钥。只有真正向上游发请求前才解密。

主要索引包括账号的状态/优先级调度索引、模型类型和名称索引、使用记录时间/账号/模型索引。使用记录保存输入、输出、缓存和总 Token；缓存 Token 从上游 usage 的 `prompt_tokens_details.cached_tokens` 或 `input_tokens_details.cached_tokens` 解析，旧数据库启动时自动补充字段。

账号监控由 FastAPI lifespan 创建独立 asyncio 任务，默认立即执行一轮、之后每 120 秒执行一次；每轮重新查询启用账号，最多 5 个并发，每个账号只发起一次请求。监控结果写入独立 `monitor_records` 表，查询接口只返回当前启用账号最近 30 条记录，不参与账号调度和真实请求统计。设置保存会通过事件唤醒任务，关闭期间不发送请求，重新开启后立即执行一轮。

## 5. API 边界

管理 API 为 `/api/accounts`、`/api/models`、`/api/usage`、`/api/monitor` 和 `/api/settings`。配置了 `local_token` 后，这些管理 API 以及 `/v1` 兼容 API 都要求 `Authorization: Bearer <token>`。

OpenAI 兼容端点包括 `/v1/models`、`/v1/chat/completions`、`/v1/completions`、`/v1/responses`、`/v1/embeddings`、`/v1/moderations`、`/v1/images/generations`、`/v1/audio/speech`、`/v1/rerank` 及 Responses 的 cancel/compact；Anthropic 兼容端点包括 `/v1/messages`、`/v1/messages/count_tokens`、`/v1/messages/batches` 和 `/v1/complete`。

兼容端点只接受 JSON。认证头由账号配置生成，客户端的协议头只按协议白名单透传；OpenAI 请求只选 OpenAI 账号，Anthropic 请求只选 Anthropic 账号。

## 6. 测试、打包和升级

测试命令为 ` .\\.venv\\Scripts\\python.exe -m pytest`，打包命令为 ` .\\.venv\\Scripts\\python.exe scripts\\build.py`。PyInstaller 使用 `--onedir`，产物位于 `dist/AIMux`；用户数据库、配置和加密数据仍位于系统用户数据目录，与打包目录分离。启动时的建表、补列和默认模型播种用于兼容旧数据库。
