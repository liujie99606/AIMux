# 常见问题（QA）

## 为什么某个账号失败一次后，Codex 就显示“正在重新连接”？

先看使用记录中的“首 Token”。如果首 Token 已经有具体耗时，但最终结果是失败，表示 AIMux 已经从上游收到并向 Codex 输出了部分流式内容，随后上游流才断开。

此时 AIMux 不会用另一个账号透明重放同一个请求。重放会使 Codex 收到重复内容；对于包含工具调用的请求，还可能导致工具被重复执行。因此 AIMux 记录该次流失败并结束连接，由 Codex 自己决定是否创建新请求和重新连接。

Codex 的“正在重新连接 1/5”是客户端自身的重连，不是 AIMux 对原始流的内部重试。它创建的新请求会被 AIMux 重新调度，并产生新的使用记录。

## “总尝试次数”什么时候会生效？

“总尝试次数”是一次客户端请求最多可进行的上游尝试次数，初始请求计为第 1 次，不是“失败后额外再试 N 次”。

- 非流式请求：连接异常、上游非 2xx 或其他上游失败都会在上限内重新选择账号。
- 流式请求：仅在首个数据块输出给客户端之前重试，包括连接异常、上游非 2xx 和首块超时。
- 流式请求首块已经输出后：不会重放，后续断流由客户端处理。

每次失败会使命中账号优先级减 1；下次尝试会按最新优先级重新选择账号，失败账号不会被强制排除。

## 如何从使用记录判断 AIMux 是否进行了内部重试？

首块前的内部重试会产生多条使用记录，它们共享同一个 `trace_id`，“重试次数”依次为 1、2、3……。首 Token 通常为 `-`，或未能正常取得首块。

如果一条记录显示首 Token 有值但最终失败，则该请求已经开始向客户端输出，不能安全地内部重试。之后若 Codex 重新连接，会出现新的 `trace_id` 和新的调度记录。
